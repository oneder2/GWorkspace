# 展陈研究、内容模型绑定与回声森林

## 研究范围与证据

2026-09-27 阅读下列可访问的馆方材料。这里归纳的是适合本项目的常见规划方法，不是对“大多数博物馆”的统计调查，也不将现实建筑尺度直接当作游戏场景尺寸。

| 馆方资料 | 直接观察 | 对 Gellaria 的设计转译 |
| --- | --- | --- |
| [卢浮宫 Cour Puget / Cour Marly](https://www.louvre.fr/en/explore/the-palace/shining-new-light-on-sculpture) | 原为户外环境创作的雕塑置于自然光庭院，错层陈列创造不同视线，重点作品占据显著位置 | 模型要由内容性质决定；保留看向远处展品的空隙，重点对象先呈现，用灯光组织主次，而不是所有物件同样大小、同样亮度 |
| [卢浮宫 Visitor Trails](https://www.louvre.fr/en/explore/visitor-trails) | 按兴趣与可用时间组织路线；个别作品不展出时可以跳过，不影响整体路线 | 连续主通道保持畅通，主题区内允许自由停留和绕行；不要求逐个点击才能前进 |
| [卢浮宫宫殿与展厅索引](https://www.louvre.fr/en/explore/the-palace) | 雕塑、陶器、不同地域/时期藏品及原址空间分别组织 | 工坊与阅览厅按语义主题再分区；每日赠语与长文章保持独立，不强行混排 |
| [V&A South Kensington 无障碍与安静空间](https://www.vam.ac.uk/info/disability-access) | 持续标识的路线、可借用座凳、安静空间、大字说明与多种感官辅助 | 展品简介分层展开；森林可暂停效果，提供完整文字阅读；尊重减少动态效果偏好 |

尝试访问 Smithsonian 指南与 British Museum 地图时遇到验证/访问限制，未将其内容当作已读证据。Guggenheim 建筑页仅返回需要 JavaScript 的页面壳，亦未据此补写研究结论。

## 平面与信息层次

结合以上案例与常见展陈方法，平面可以按下面四种组织方式比较。此表是设计分析，不是馆方给出的普适规范。

| 组织方式 | 合适内容 | 代价与使用边界 |
| --- | --- | --- |
| 单线串联 | 时间线、事件经过、有严格前后依赖的故事 | 容易理解但难以跳读；不适合把所有独立项目硬排成一条长故事 |
| 主轴加侧室/侧湾 | 可独立理解的主题收藏 | 主轴负责定向、侧湾负责停留；必须保持出口可见和侧向回到主路的空间 |
| 中心庭院辐射 | 大型镇馆作品、多个可以自由选择的主题 | 中心地标帮助重新定位，但高物体可能遮挡后方区域，重复回中心也会增加行走 |
| 自由散点/环境叙事 | 轻量片段、声音、自然环境体验 | 偶遇感强，但不能依赖所有人都看到某一时刻的内容；必须提供稳定阅读入口 |

内容分区可按年代、地域、材料/媒介或主题进行。GWorkspace 的项目并不构成必须按年代阅读的历史，所以工坊按用途/主题分区；文章按讨论主题归组，赠语作为低阅读负担的入口区。碎片化留言没有足够的线性叙事关系，适合自由散点的森林。灯光、材质和简介长度都服务于这些差异，而不是仅用不同颜色标记同一种展台。

信息也分三层：远处用轮廓判断主题；靠近出现标题与摘要；主动打开才显示模型寓意、时间、角色、亮点和原文链接。这样主通道不承担全文阅读的负担。

两个实体馆采用“入口定向 → 连续主轴 → 主题侧湾 → 下一主题”的结构。入口说明主题，侧湾承载慢阅读；通道、展台碰撞缓冲和视线避让共用计划。每区至多四件作品，按数据库模型的 `zone` 分组，精选项目优先排列。旧记录没有新模型时按既有内容类型分组，兼容旧服务。工坊保留铜色轨道与钢材；阅览厅保留木色书案与靛蓝书廊。这里不直接复制卢浮宫台阶：当前角色移动没有楼梯功能，采用无高差通道和模型内部错层来取得层次。

```text
入口 / 主题路线
       │
   展品侧湾 ─ 主通道 ─ 展品侧湾
   可绕行      │       可停留
          主题连接廊
              │
          下一主题区
```

回声林地单独渲染，不创建展台、展品碰撞盒、展厅隔墙、分室编号或弹出展签。石径与低位光点提供方向；树木的横向退距留下主路径，树干参与碰撞，遮挡角色的树冠自动淡出。森林的纹理感来自模型、光照、薄雾与远近层次。

## 数据库与生命周期

迁移 `021_gellaria_artifacts.sql` 新增 `gellaria_artifacts`。`id` 为稳定 UUID；`project_id` / `blog_id` / `capsule_id` / `placement_id` 四个可空外键必须恰有一个非空，每个外键各自 UNIQUE，删除源记录时级联删除。记录包括 `source_hash`、JSON `spec`、`revision`、`generator`、创建/更新时间。

项目、文章、每日赠语及外部展陈的创建/更新在模型层同步模型配方，因此写作工作台发布文章也会触发；不是只在某一条 HTTP 路由里触发。仅已发布且包含 `gellaria` surface 的项目、已发布文章、active 赠语和实体馆内已发布外部记录参与生成。撤回发布会在公开查询中过滤掉内容，其绑定保留以支持重新发布。GET 接口不生成模型、不写数据库。

`spec.version = 2` 为受限程序化模型配方；`generator = semantic-rules-v2.1` 是生成算法版本。标题/分类匹配权重高于全文，避免长文中偶然出现的技术词压过主要主题。表单有十一种语义形态：空间沙盘、检索台、节点交换机、出版机、计划时钟、掌上终端、苗床、叙事灯笼、结构齿盘、书册与每日光页。每条记录保存独立 seed、比例、构件数、配色、语义依据和转译说明。同一绑定修改文字后保留 ID/seed，内容哈希变化才增加版本。

这是保存到数据库的确定性程序化建模，不是手工雕刻的独立 GLB，也不声称调用了外部 AI。既有项目 Agent 建模流程、`gellaria_project_models` 和旧 `modelSpec` 字段保留；新的 `artifactSpec` 优先用于三维渲染。规则不确定时使用书册，不编造作品功能。以后可以在受限配方之上接入审核或人工建模。

公开 `/api/public/world` 在原字段之外增加：

```json
{
  "artifactId": "artifact:<uuid>",
  "artifactRevision": 1,
  "artifactSpec": {
    "version": 2,
    "seed": 38215,
    "form": "research-desk",
    "zone": "知识与推理",
    "colors": ["#7b9cbd", "#b9b2d7", "#e1f1ed"],
    "proportions": { "width": 0.99, "height": 1.01, "depth": 0.94 },
    "detail": { "count": 4, "rings": 2 },
    "evidence": ["学术", "检索"],
    "caption": "以文献层、检索透镜与证据连线转译「学术检索工具」的主题。",
    "featured": true
  }
}
```

这是字段示意，不是数据库记录副本。前端不再以简历列表覆盖世界展陈列表；简历只补充匹配项目的详情和媒体，世界 API 的发布选择、顺序和绑定为准。每日赠语也由世界 API 提供绑定；成功返回世界内容后，pulse 不再用无绑定记录覆盖它。旧 API 缺少新字段时仍可使用旧模型。

## 森林文字事件

每段公开文本在三维空间内拥有独立 X/Y/Z、高度、字号、时序偏移；下一次完整循环时换位，显现过程中不突然跳位。位置是以内容 ID 为种子的可重现随机采样。文字沿相机方向朝向访客，但保留世界坐标、透视和深度遮挡；不是覆盖在屏幕上的 DOM 标签。

字形以本地系统字体绘入 Canvas atlas，再生成每字一组四边形。使用 Unicode grapheme 分割，避免拆断 emoji/组合字符。着色器依次显现、停留、擦除；两层延迟重影提供视觉回声。桌面最多五段、手机最多两段附近文本可见；每段空间摘录最多 72 个字形，完整公开摘要保留在“阅读回声”。这是视觉回声，不自动播放留言、合成语音或音乐。

“暂停回声”冻结时序，阅读完整回声时暂停角色移动与文字事件；系统减少动态效果偏好使用完整、静态文本并关闭重影。读取来源只允许 HTTP/HTTPS。森林继续复用访客/登录用户的角色形象和 `memory-grove` 房间状态。

手机端每行最多八个字形，收拢文字横向范围并按距离补偿最小字号；桌面每行最多十二个字形。动态偏好使用服务端一致的首屏快照，并订阅系统设置变化，避免减少动态效果造成 hydration 不一致。

## 迁移与运行

后端启动在迁移完成后执行幂等回填；也可单独运行：

```sh
bash scripts/run-with-backend-node.sh npm --prefix backend run gellaria:backfill-artifacts
```

本地首次回填前使用 SQLite 在线备份保存 `before-artifacts.db`；只应用新增迁移后回填 41 条记录（9 个项目、7 篇文章、25 条赠语），外键检查无错误。浏览器验证服务使用数据库副本，避免测试交互写入实际内容。远程服务器尚未应用本轮改动。

现有每区 12 条公开内容上限保留，未扩大查询范围。森林摘录来源是已公开且已审核的内容；完整阅读指完整公开摘要，不是私人文章或留言的未公开原文。

## 验证命令与结果

- `npm run test:gellaria`：17 个文件、59 项测试通过。新增 Unicode 字形、时序、位置范围、树干避让、绑定保留、pulse 不覆盖绑定、语义分区和配方边界测试。
- `bash scripts/run-with-backend-node.sh node backend/scripts/check-gellaria-artifacts.js`：临时数据库验证迁移重跑、自动绑定、改名、版本、删除级联、发布范围、幂等回填；实际 HTTP GET 验证新配方、旧接口与缓存响应。
- `npm run check:world-content` 和 `npm run check:resume`：既有公开内容、简历导入和兼容性检查通过。
- `npm run lint:gellaria`、类型检查与生产构建用于检查渲染代码。

浏览器使用本地生产构建与实际本地数据的副本。截图位于 `output/playwright/`：`bound-workshop.png`、`bound-archive.png`、`echo-forest-reveal.png`、`echo-forest-mobile.png`、`echo-reader.png`。测试覆盖进入场景、Unicode 字形显现、三维文字重影、暂停/继续、完整阅读与 Esc 关闭、减少动态效果和手机构图。未进行真机 GPU 性能基准，不将桌面浏览器的小屏截图当作真机性能结论。
